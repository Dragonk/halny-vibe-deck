# Halny Vibe Deck (branch next) — user-reported defects round 15 (1.99.22), re-verified in code

| # | Report | Verified root cause | Fix |
|---|--------|--------------------|-----|
| R1 | agent action messages duplicate, sometimes 10-15x (chat paste) | `history/entryAdded` re-delivered on resync/reconnect was appended to the mirror AND re-emitted `ToolCallStarted`; the client/engine appended every delivery to `tool_calls` with no id check | three-layer dedup: appserver `push_entry` skips an already-known entry id (test `entry_added_replay_deduped`); engine `apply_slot_event` and client `state.rs` skip `ToolCallStarted` when the tool-call id already exists |
| R2 | "open elsewhere" still shows on Windows for our own session | the lease holder PID is the real app-server process; on Windows the spawned uv `.exe` shim spawns python as a GRANDCHILD, so `conn.child_pid()` ≠ lease PID and the badge lit up for ourselves | `Projection.own_pids` now collects BOTH the launcher child PID and the `processId` from the wire `initialize` response (`os.getpid()` in server.py); shared `lease_held_elsewhere()` helper used by notification + subscribe paths |
| R3 | stop (✕) must kill the session incl. subprocesses | `Conn::drop` used `Child::kill()`, which on Windows kills only the launcher shim, not the python grandchild | on Windows `taskkill /F /T /PID <child>` (whole tree) before `kill()` |
| R4 | green dot on the open tab, not where the agent runs; ✕ missing | dot was keyed on `current == idx` (open tab); ✕ only on `m.busy` | both now keyed on `agent_on = busy || stopping || (status == "connected" && has_agent)` — per-session, from the snapshot |
| R5 | switching sessions freezes the app | each structural event during a switch/resume triggered a full snapshot refetch + re-render; the UI also waited for the server before showing anything | shell event loop coalesces refetches (one in flight, one queued); sidebar sets `switching_to` immediately and the chat renders a "Loading session…" marker (i18n, 6 langs) until the refetch lands |
| R6 | scrolling in the active session misbehaves | auto-scroll fired on every chat mutation with a 120px near-bottom window — during fast streaming the user was yanked down; the observer also early-returned on non-chat mutations | `__vdUserUp` intent flag: wheel-up/touch-up inside the chat disables auto-scroll until the user returns within 24px of the bottom; observer scans all mutations instead of returning on the first non-chat one |
| R7 | switching md preview to edit freezes the app | `CodeEditor` recomputed the FULL syntax highlight + gutter on every parent re-render (any background signal), and `vdEdSync` measured every line with a DOM range in wrap mode | highlight/gutter cached per (file, text) in the component; wrap-gutter walk capped at 4000 lines (falls back to plain scroll sync) |
| R8 | docx h-scrollbar only visible after scrolling to the very bottom; at max zoom pages still overflow; want fit-to-width default with 1:1 option | the scroll container's own scrollbar sits at the end of the content; no view-mode control existed | sticky `position:sticky; bottom:0` h-scrollbar inside `.preview-doc` (mirrors scrollLeft both ways, shown only when content overflows, `DOC_HSCROLL_JS`); toolbar toggle Fit (default, persisted `vdDocFit`) / 1:1 — fit squeezes `.doc-page` to 100% width, 1:1 keeps real page width + always-visible sticky scrollbar |
